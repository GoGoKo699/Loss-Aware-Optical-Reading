# Workspace rules

Read README.md, CLAIM_STATUS.md, docs/PHYSICAL_SETTING.md, SOURCE_AUDIT.md, and
work_orders/CURRENT.md before changing science. The repository, not a prior chat,
is the working source of definitions, evidence, and task boundaries.

Use a new branch for a bounded task. Record the starting commit and dirty status.
Do not reset another branch, rewrite history, delete evidence, change privacy,
select a license, or publish a release without explicit authorization.

Protect original archives, baseline/, and frozen results/. Use scripts/reproduce.py
for fresh runs. It refuses existing output directories and checks protected hashes.
The import manifest checks current protected content; an authorized later scientific
change must include a visible manifest/update record, never a silent hash refresh.
The original archive hash must never be updated to bless different source bytes.

Do not turn a numeric check into a universal proof, a bound into an attained optimum,
a forecast into calibration, or a synthetic example into experimental evidence.
Keep resource classes, priors, phase references, input/output planes, and trial
counting intact. A code refactor cannot silently strengthen a scientific claim.

Do not assume multiphoton computing, idlers, occupied bypass rails, quantum memory,
or repeated calls to one hidden setting. A different access model needs a new
scoped task and separate claims. Laboratory feedback precedes hardware execution.

Prefer simple mechanism explanations and equations with defined symbols. Avoid
unsupported GitHub math macros and math in headings. Use separate display blocks.
Keep archival links optional. Do not import earlier discarded research branches
into the main scientific narrative merely for historical completeness.

At completion report exact files, checks actually run, remaining limitations,
and the commit. Do not leave uncommitted results or claim CI passed from its
configuration alone. Stop at the authorized task boundary.
