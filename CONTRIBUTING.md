# Contributing

This is a private working repository. No redistribution license has been chosen.
The project owner controls access, publication, and licensing decisions.

Start with work_orders/CURRENT.md. Use one branch and one reviewable change for
one bounded task. State assumptions before conclusions and preserve counterexamples
and failed checks when they affect the conclusion. Do not repair a possible
scientific inconsistency silently during a presentation edit.

Run the import-integrity test, engineering unit tests, and safe reproduction before
proposing a change. New mathematics needs independent tests and a written argument;
passing legacy tests is insufficient. Changes in a theorem, resource model, or
experimental protocol must update the claim ledger and relevant work order.

Never overwrite archived outputs. Fresh runs belong in results/runs/, not the
reference directory. Raw laboratory data need a separately reviewed acquisition,
privacy, and retention plan. Do not commit credentials, device-control secrets,
or unreviewed personal data. Synthetic examples retain their labels.
